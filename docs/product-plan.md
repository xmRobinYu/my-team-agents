# my-team-agents 产品规划

> 本文档与仓库同步；仓库为唯一事实来源（single source of truth）。
> 源文件：`docs/product-plan.md`。飞书侧内容由 `just sync-docs` 覆盖更新。

## 1. 产品定位

**多租户、公司级 Agent Team 平台**：以数字员工（Agent）为组织成员，让 Agent 与
实体员工在项目工作区中协作，并把协作过程中的知识、成本与成果沉淀为组织资产。

一句话定位：

> 以**团队型数字员工**为起点，以项目工作区与团队知识为核心，逐步扩展到职能型与
> 个人分身的企业级 Agent Team 平台。

## 2. 三类数字员工（对标 Finxone）

| 类型 | 代表谁 | 对谁负责 | 知识/数据边界 | 我们的阶段 |
|---|---|---|---|---|
| 团队型 | 项目 / 团队 / 业务群 | 团队 | 项目资料、讨论、成果、团队经验 | **主线，V1 交付** |
| 职能型 | 总行 / 部门（人力、财务等） | 组织职能 | 官方制度、岗位技能、公共知识 | V2 |
| 分身型 | 具体个人 | 本人 | 个人资料、偏好、个人授权 | V3，需授权体系成熟 |

三类之间的差别不是提示词模板，而是**归属、责任与授权边界**。这一区分决定领域模型
演进方向（见 `CONTEXT.md` 与本仓库 `packages/domain`）。

## 3. 能力分层

```text
控制面   DigitalWorker / JobTemplate / Skill / KnowledgeSpace / Delegation
协作面   Project / Group / Task / Handoff / Report
执行面   RuntimeAdapter → Pi / Claude CLI / Codex CLI / DSH CLI
```

- 执行面只负责“把一次 run 跑好、跑成结构化事件”。
- 协作面负责归属：项目拥有工作区，群聊只是视图。
- 控制面负责“这个数字员工是谁、能做什么、代表谁”，当前为规划层，尚未建模。

## 4. V1 范围（已确认）

V1 目标：**把基础架子搭起来并跑通协作闭环**，其余简化或延后，但保留扩展接口。

V1 交付：

1. 运行时契约与适配器：Pi（唯一完整 loop）、claude/codex/dsh CLI 接入。
2. 领域骨架：Tenant / Project / Group / Member / Task / Handoff。
3. 链路中枢：任务入队 → 执行 → 结构化交接 → 停滞看门狗。
4. 每日自评估：从 Pi 会话日志产出成本与用量报告。
5. 工程治理：严格类型、护栏自检、规则文件变更留痕。

V1 明确不做（保留接口，不实现行为）：

- 技能市场 / 工具市场；
- 晋升体系与能力包仓库；
- 完整五层成本归因账本；
- 个人长期记忆与分身型授权代理；
- assistant-ui 前端集成；
- 服务端与多租户鉴权。

## 5. 模块规划（对标 Finxone 平台功能表）

| 模块 | Finxone 功能 | 我们的处置 | 阶段 |
|---|---|---|---|
| 数字员工 | 员工视图 / 员工管理 | 先有 Member（运行身份），后续拆出 DigitalWorker 控制面 | V1→V2 |
| 技能 | 技能视图 / 管理 / 审核 | 本地技能配置 → 版本化 → 审核；市场延后 | V2 |
| 工具 | 工具视图 / 维护 | 工具注册与授权优先于“市场” | V2 |
| 模型 | 模型视图 / 配置 | 模型配置与预算约束优先；多模型路由延后 | V1.5 |
| 审计 | 审计日志 / 用量统计 | 运行日志已具备；升级为治理审计（actor/subject/授权/副作用） | V2 |
| 用户与组织 | 岗位模板 / 用户管理 / 组织架构 | 岗位模板映射 JobTemplate；虚拟团队汇报线映射 Group 视图 | V2 |
| 对话 | 对话主窗口 | assistant-ui（react-pi）集成 | V1.5 |
| 记忆 | 我的记忆 | 分层记忆（个人 / 团队 / 组织），带 ACL 与可撤销授权 | V3 |
| 任务 | 定时任务 | 依赖持久化队列与幂等；随后加调度器 | V1.5→V2 |
| 知识 | 知识管理 | 藏经阁 v1 = LLM wiki + RAG；按权限检索、带出处 | V1（已规划） |

## 6. 关键产品原则

1. **交接必须声明，不能从散文里猜。** Agent 通过 `handoff_to` 表达意图；模型在句子
   里写“@bob 看下”不构成派工。
2. **护栏是确定性代码，不依赖模型自觉。** fanout / depth / budget / revisit 上限在
   派发前判定。
3. **项目拥有工作区，群聊只是视图。** 重建或解散群不触碰工作区、会话与产物。
4. **未知事件不丢弃。** 上游不认识的事件以 `type:"unknown"` + `rawType` 保留。
5. **反馈先形成建议，人工评审后才改生产配置。** 不做“用户反馈→自动改提示词/权限”。
6. **成本归因贯穿始终。** `tenant / project / member` 三键随每条用量流动。

## 7. 成功判据

V1 是否成立，不看页面数量，看这四件事：

- 一个任务能否被排队、执行、并按声明交接给下一个 Agent；
- 失控扇出能否被确定性上限挡住，并留下可审计记录；
- 一次日常运行能否产出按租户/项目/成员归因的成本报告；
- 仓库门禁（构建、类型、测试、CLI、护栏自检）能否在干净检出上一键通过。
